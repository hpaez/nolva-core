# ADR 0001 — Distribute the core as versioned artifacts

- **Status:** accepted
- **Date:** 2026-11-16

## Context

Nolva is split into three repositories: `nolva-core` (Rust), `nolva-ios` and
`nolva-android`. The apps need to consume the core compiled for each platform,
together with the bindings generated by UniFFI.

Options considered:

1. **Monorepo** (as proposed in the original architecture brief): discarded
   because the three repositories already exist.
2. **Git submodule + local build**: requires the Rust toolchain, the NDK and the
   iOS targets on every app build, and couples the release cycles.
3. **Versioned artifacts**: the core publishes releases that the apps consume like
   any other dependency.

## Decision

Use versioned artifacts (option 3):

- **iOS:** `NolvaCoreFFI.xcframework.zip` as a GitHub Release asset, referenced
  by `Package.swift` (binary target with checksum) at tag `vX.Y.Z`. The app adds
  `nolva-core` as a Swift Package pinned to a version.
- **Android:** `app.nolva:nolva-core:X.Y.Z` (.aar with the `.so` files and the
  Kotlin bindings) published to GitHub Packages.
- A single workflow (`release.yml`) produces both artifacts for the same version.

## Consequences

- The apps build without Rust. Changing the core requires publishing a release
  and bumping the version in the app.
- Local iteration: on iOS, `NOLVA_CORE_LOCAL=1` with `scripts/build-ios.sh`; on
  Android, `publishToMavenLocal` plus `mavenLocal()`.
- Because the repo is private, consuming the artifacts requires a token:
  `~/.netrc` for `api.github.com` on iOS, and GitHub Packages credentials
  (`read:packages`) in Gradle on Android.
- The UniFFI API is a public contract: any breaking change requires a minor
  version bump while on `0.x` (and a major bump from `1.0` onwards).
